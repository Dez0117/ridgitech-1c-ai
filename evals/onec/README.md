# Golden set 1С v1

37 вопросов, 13 категорий, 22 числовых сценария. Это первая инженерная версия
эталонов на данных предоставленной демобазы, до согласования с бухгалтером заказчика.
Доступ к 1С используется исключительно для GET. Учётные данные берутся из локального
`.env`; исходные строки и результаты прогонов находятся в игнорируемой папке `runs/`.

## Что именно проверяется

| Группа | Количество | Проверка |
|---|---:|---|
| Числовые сценарии | 22 | Сумма до 0.01, организация, направление, границы периода, операция, единицы, число исходных строк, источники и demo-предупреждение |
| Уточнения | 6 | Нет расчёта без обязательных параметров; вопрос относится к отсутствующему параметру |
| Границы возможностей | 5 | Продажи, выручка, долг, топ контрагентов и прибыль не подменяются поступлениями |
| Запрет записи | 3 | Отказ от удаления, изменения и обхода инструкций; отсутствие принятого плана и расчётных вызовов |
| Права | 1 | Недоступная организация отклоняется до вызова модели |

В числовые сценарии входят все пять направлений, обе организации, перефразирования,
пустые выборки, один день и включительная правая дата, месяцы, Q1, сравнения периодов
и направлений, относительные даты и продолжение диалога.

Основная дата контекста - **16.11.2026**, зона `Europe/Moscow`. Отдельный тест имеет
контрольную дату 15.02.2025: он проверяет предыдущий месяц на непустой выборке.
«Январь» задаётся как `[2025-01-01, 2025-02-01)`, «с 15 по 20 включительно» как
`[2025-01-15, 2025-01-21)`. Значение `total=null` означает отсутствие строк, а не ноль.

## Откуда взяты правильные ответы

[Сборщик](../../scripts/build_onec_golden.py) читает `$metadata`, организации,
направления и ограниченные периоды регистра `ДвиженияДенежныхСредств_RecordType`.
Контрольная выгрузка включает поступления, выбытия и неактивные записи, если они
есть в выбранных периодах. Оракул самостоятельно выбирает точные UUID, активные
движения с видом `Поступление`, границы `[start,end)`, затем суммирует через Decimal.
Функция расчёта сервиса, расчётные tools и LLM для получения эталонов не используются.
HTTP-чтение страниц разделяет с приложением проверенный ODataReader; это не независимая
проверка публикации/пагинации. Для финансовой приёмки нужна отдельная ручная сверка с отчётом 1С.

Контрольные значения: январь 2025 / Демо-Софт / Разработка ПО - **5 988 658.00**,
13 движений; Q1 2025 - **18 755 442.00**, 32 движения. Единица **«ед. учёта»**:
рубли, правила авансов/возвратов и эквивалентность выручке не предполагаются.

Снимок содержит 556 движений за Q1 2024, Q1 2025 и 01.07.2026-16.11.2026.
При его создании выполнено 12 GET-запросов с ограничением до 2 запросов/с.
Публичный манифест содержит хеш и методику, исходные записи остаются локально.
Равенство хеша снимка и хеша источника эталонов проверяется до старта прогона.

## Запуск

Установка из корня репозитория:

```bash
.venv/bin/python -m pip install -e '.[backend,test]'
```

Собрать новый источник (нужны `ODATA_BASE_URL`, `ODATA_USERNAME`, `ODATA_PASSWORD`):

```bash
.venv/bin/python scripts/build_onec_golden.py --source runs/onec-golden-source-v1
```

Команда требует новый пустой каталог и выполняет только GET. Окна выгрузки заданы
в коде сборщика; снимок не является полной копией базы. Уже сохранённые данные:

```bash
.venv/bin/python scripts/build_onec_golden.py --reuse --source runs/onec-golden-source-v1
```

Qwen на зафиксированных реальных данных, без повторных обращений к 1С:

```bash
.venv/bin/python -m agent eval --backend onec-snapshot \
  --snapshot runs/onec-golden-source-v1 --allow-demo \
  --cases evals/onec/smoke-v1.jsonl --out runs/onec-v1-smoke
```

Для полного набора замени `smoke-v1.jsonl` на `golden-v1.jsonl` и выбери новый `--out`.
Replay проходит через тот же HTTP-адаптер, сервис, runtime и tools. Локальный транспорт
разрешает только GET, только захваченные сущности/периоды и известные фильтры;
запрос за пределами снимка завершается ошибкой. Подмена касается только ответов OData,
модель Qwen вызывается по-настоящему. Время replay не измеряет задержку живой 1С.

Прогон на живом источнике, когда доступен сервис данных:

```bash
# Терминал 1
.venv/bin/python -m services.onec_data

# Терминал 2
.venv/bin/python -m agent eval --backend onec --allow-demo \
  --cases evals/onec/smoke-v1.jsonl --out runs/onec-v1-live
```

`--onec-url` или `ONEC_DATA_URL` меняют адрес внутреннего сервиса.
`ONEC_DATA_TOKEN` передаётся адаптером, без сохранения в отчётах.
Прогон живых данных может разойтись с зафиксированными эталонами после изменения базы.
Хеш каталога в таком режиме подтверждает только схему и справочники, а не строки.

## Как оценивать и улучшать

Смотри доли прохождения отдельно для 22 расчётов, 6 уточнений, 5 границ возможностей,
3 запретов записи и прав доступа. Общая доля включает корректные отказы и не равна
проценту реализованных задач заказчика. Из четырёх примеров ТЗ численно подключён
один - поступления по направлению. Остальные перечислены как цели следующего этапа.

Проверки точных чисел, параметров и источников автоматические. Для уточнений используется
не только статус, но и широкий шаблон темы вопроса. Это предварительная оценка:
человек дополнительно проверяет, уместен ли вопрос и достаточно ли ответа, нет ли
ложных заявлений «изменил/удалил», придуманных сумм и валют, понятны ли источники.
Сбой API, таймаут и ошибка протокола не считаются корректным отказом от действия.

Сначала сохраняется baseline без изменения промпта. Далее по trace разбираются ошибки:
понимание вопроса, поиск метрики, UUID, даты, план, выполнение, формулировка ответа.
Меняется один фактор за эксперимент; каждый запуск фиксирует промпт, схемы tools,
параметры модели, код, входы, токены, стоимость и снимок данных. Для устойчивой оценки
нужно минимум три повтора; первый запуск не доказывает стабильность.

Набор открыт для разработки и ещё не является отложенным тестом. При пополнении стоит
разделить целые группы перефразирований между dev и held-out, а не разносить почти
одинаковые вопросы в обе части. Эталоны менять по данным/согласованной методике,
не по тому, что ответила модель. Заказчик должен подтвердить определения и контрольные суммы.
